# P0 runtime layout

All enabled application services use `/opt/deadlock-brain/current/bin`. The base serve unit names `%h/.config/deadlock-brain/brain-serve.json`, which remains the sole live serve configuration. Site and maintenance already name that file. It stays writable by the operator because candidate activation still atomically rewrites its release pins until P7. The obsolete serve ExecStart drop-in and unreferenced `/etc/deadlock-brain/brain-serve.json` are removed during installation. No live configuration content is copied into this repository.

`brain-release` sets `current` to the verified `/opt/deadlock-brain/releases/<SHA>` and `maintenance-current` to `/opt/deadlock-brain/current/bin`. The latter is a compatibility alias for the disabled maintenance unit's flat binary path, not a separate release track. It follows every current switch, including rollback. Existing dual-layout build proofs and historical folders remain for compatibility and separately authorized cleanup. Recovery accepts pre-P0 journals and restores their previous targets.

Serve fetches secrets in-process through `dl-token-secrets`. The actually resolved library supports `credential_fd` and an absolute `credential_path`, but not `CREDENTIALS_DIRECTORY`. The approved normal `/etc/deadlock-brain/infisical-serve.json`, mirrored in this directory, points `credential_path` to `/run/user/1000/credentials/brain-serve.service/infisical-token`. It reuses the existing transport/project settings and contains only references, paths and ordinary configuration, not secret values. Only the serve unit's `--infisical-config` flag changes; the original Infisical config and maintenance path stay unchanged. Runtime verification compares that path with the unit's credential directory without reading credential contents. Site uses its existing peer-authenticated Postgres configuration; browser-consent has only accessibility-bus and interval configuration. Both receive the same credential facility but do not need secret-export wrappers or unnecessary copies of all Infisical secrets in their environments. Their executable paths move to the shared release without changes to arguments or runtime logic.

Recorded MemoryMax values: serve 512M, site 256M, browser-consent 64M, maintenance 8G. The measured inventory reported maintenance at 2.7 GB RSS and its activation child at approximately 2.9 GB. The intended maintenance budget covers their combined process group plus margin. These user-unit limits are recorded, not enforced on this OpenVZ/cgroup-v1 host. MemoryCurrent and MemoryPeak remain unset; P1's independent memory-controller probe demonstrated allocation beyond its configured limit. Enforcement moves to the separately authorized P0b system-unit package after P0. Maintenance is currently inactive, so no new tick peak is claimed.

The orchestrator explicitly waived maintenance activation testing on 2026-10-12: no maintenance tick or Rust maintenance change, and no recurring timer enablement. Keep `99-user-disabled-20261012.conf` and the maintenance FD5 ExecStart wrapper unchanged. P7 replaces that path. Only maintenance memory accounting and its cap change in P0.
