Scope
The reserved sparse migration entry is version 4. The previously unapplied P4 migration is named 2026-10-12-brain-gamefacts-p4-patches-v1.sql. Core migration v1, current_* views, storage/core, extractors and productive tool implementations are unchanged by this branch.

The nullable valid_from_patch and valid_to_patch columns reference generic canon.entity patch identities. Identity guards check kind/key and protect referenced identities against renaming/retyping. Existing facts stay unassigned; the upgrade probe verifies unchanged old fact values and relfilenode. No timestamp/revision mapping, row backfill, persisted serving projection or refresh writer was added. Grants for assigning these boundaries were not added.

Reference-index contract
The serving migration requires the coordinated P4 version-2 extractor format:
patch_change_r<lowercase SHA-256 hex of normalized_reference UTF-8>_<physical_statement_index>
This stores a reference fingerprint, not resolved hero membership. It must be released coherently with the parent's version-2 extractor/re-extraction checkpoint. Old experimental statement keys are not interpreted as version-2 keys.

The additive fact_patch_reference B-tree covers (stat_key COLLATE "C", entity_id). A hero's currently coherent published aliases determine fingerprint-prefix lower/upper bounds. A correlated LATERAL candidate query applies these bounds to serve.current_fact before JSON validation. DISTINCT ON includes stat_key, so this narrowing preserves latest-row selection. The original JSON reference must still equal the current alias; the fingerprint is not treated as authoritative identity. Published-alias conflicts hide ambiguous references. Patch raw/run/extractor coherence, official metadata receipts and the published_receipt quarantine boundary remain required. Catalog metadata is checked in one per-patch aggregate with the three expected pointer receipts.
