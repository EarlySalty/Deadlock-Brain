# P9 receipt audit

Goal: daily verification of at most 200 published canonical receipts against their immutable raw objects, quarantine mismatches or missing raw locators and exclude quarantined receipts from serving. Record audit outcomes in ops. No ingestion data-quality changes or other packages' work.

Acceptance: deliberately corrupt one receipt in isolated PostgreSQL, execute the real audit, and prove exactly its fact disappears from serve results while canon history remains. Production acceptance additionally requires an actual system-unit run below 120 seconds and 200 MB measured with the enforced cgroup-v1 peak. Integration and deployment remain blocked until P1 is live and the local merge gate allows the exact integration state.

## Contract and implementation

P1 checkpoint 3a0740be219fb4aceb304e8020501dcd7281fbd7 was integrated by merge commit 24e6c309. Existing parser functions, signatures and extractor version remain unchanged. Audit outcomes are exactly `match`, `mismatch`, `locator_not_found` and `unsupported_locator_kind`. Mismatches and missing locators quarantine; an unknown locator kind is counted without quarantine and makes the job partial. Parser, blob-limit and database failures fail the job rather than falsely classifying a missing locator. No current-extractor-version restriction applies to historical receipts.

The runtime groups the bounded sample by raw object, reads one bounded blob per group, checks raw SHA256 and performs raw-locator verification outside the writer lock. Audit results are inserted in one statement per object. A dedicated detached PostgreSQL connection owns the audit session lock; the existing writer lock is acquired immediately before persistence. No raw-object row lock requiring ingest UPDATE privileges is used.

The additive migration creates immutable ops audit results and canon receipt quarantine. Only its security-definer trigger writes quarantine. Ingest cannot directly insert, update or delete quarantine rows. Current fact, alias and relation views exclude quarantined receipts, and the hero projection refreshes atomically with new quarantine. Receipt RLS makes existing tool evidence hydration fail closed for quarantined identity citations. The additional audited views filter identity and ability citations. Canon facts remain stored unchanged.

The system service/timer instances use the P0b system-unit contract, existing credential loading, a hard process time limit and enforced memory accounting. They are not installed or enabled yet. Independent security/lifecycle review found no concrete defect. Both counters must be readable or the unit fails. The peak includes collector usage; failed job executions skip collection and do not qualify as successful-run acceptance. Neither swap enforcement nor live memory bounds are claimed. Production acceptance must compare the recorded cap with 536870912 bytes and the peak with the stricter 200000000-byte ceiling. The 03:17 daily calendar expression passed systemd-analyze calendar.
