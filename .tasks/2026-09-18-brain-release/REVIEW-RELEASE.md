# Release-Review des Orchestrators

## R4: Event wechselt Patchidentität

In der bisherigen Folgemigration verarbeitet `brain.capture_patch_evidence` bei UPDATE nur `NEW`. Wechselt ein bestehendes Event seine `patch_external_id` von Quelle A zu B, wird nur der neue kanonische Reviewschlüssel gesperrt/invalidiert. Ein Entwurf zu A kann unverändert bleiben; `evidence_revision` zu A sieht die neue, zu B gehörende Revision nicht. Neuer SQL-Regressionstest: zwei Quellen/Reviews, Event unveränderter event_hash wandert von URL A nach URL B; beide Reviews müssen `needs_revalidation` werden und der Speicherschutz muss die Entfernung aus A erkennen. Alte und neue Zugehörigkeit nachvollziehbar erhalten, keine Event-ID-Umschreibung, Locks deterministisch geordnet. Ursprüngliche Migration unverändert, bei Bedarf neue dritte Migration statt ausgerollte Migration umzuschreiben. Derzeit noch keine der Evidenzmigrationen produktiv angewendet.
